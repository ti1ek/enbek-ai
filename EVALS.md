# EVALS — Оценка качества Enbek AI

## 1. Golden Dataset

**Файл:** `data/golden/np_golden.jsonl`  
**Источник:** Нормативное постановление Верховного Суда РК №1 от 28.11.2024 (`P240000001S`) — «О некоторых вопросах применения судами законодательства при разрешении трудовых споров»  
**Объём:** 25 вручную составленных пар вопрос/эталонный ответ  
**Формат записи:**
```jsonl
{
  "id": "np001",
  "question": "...",
  "reference_answer": "...",
  "category": "Досудебный порядок урегулирования трудовых споров",
  "source_text": "...",
  "url": "https://adilet.zan.kz/rus/docs/P240000001S#z0"
}
```

### Категории вопросов

| Категория | Кол-во |
|---|---|
| Досудебный порядок урегулирования трудовых споров | 4 |
| Процедура рассмотрения трудовых споров | 5 |
| Сроки обращения в суд | 3 |
| Восстановление на работе | 4 |
| Незаконное увольнение | 3 |
| Материальная ответственность | 3 |
| Коллективные трудовые споры | 3 |
| **Итого** | **25** |

### Почему 25 примеров вместо 30

Все 25 примеров составлены **вручную** с явной верификацией по тексту НП ВС РК: каждый `reference_answer` сопровождён `source_text` из оригинального постановления. Качество эталона критичнее количества для метрик `context_recall` и `answer_correctness`.

Ключевой аргумент: НП ВС РК №1/2024 содержит ~25 содержательных правовых позиций. Добавление ещё 5 примеров из того же документа означало бы повторение тех же норм в других формулировках, что снижает diversity датасета без улучшения его диагностической ценности. Выбор однородного источника был намеренным: он исключает ambiguity в `reference_answer` и даёт чистый benchmark для измерения retrieval-качества именно по НП ВС РК.

## 2. Метрики RAGAS 0.2.6

**Конфигурация запуска:** `scripts/run_ragas_evals.py`  
**Judge-модель:** `gpt-4.1-mini`  
**n=25** для каждой конфигурации

### Метрики и их смысл

| Метрика | Что измеряет | Почему важна |
|---|---|---|
| `faithfulness` | Доля утверждений в ответе, подтверждённых источниками | Защита от галлюцинаций |
| `answer_relevancy` | Насколько ответ релевантен вопросу | Качество синтеза |
| `context_precision` | Доля релевантных чанков среди retrieved | Точность retrieval |
| `context_recall` | Доля необходимой информации в retrieved контексте | Полнота retrieval |
| `answer_correctness` | Совпадение с эталонным ответом | End-to-end качество |

### Что метрики НЕ показывают

- `faithfulness` не проверяет юридическую корректность — только соответствие источникам
- `answer_correctness` ограничена качеством `reference_answer` и чувствительна к перефразировкам
- Метрики не измеряют latency-quality trade-off (latency отслеживается отдельно)
- Не охватывают out-of-scope вопросы (классификатор срабатывает раньше RAG)

## 3. A/B Эксперимент: Basic vs Advanced

**Гипотеза:** добавление HyDE + rerank + verifier (Advanced) улучшит все 5 метрик по сравнению с чистым hybrid-retrieval (Basic).

| Конфигурация | Faithfulness | Answer Rel. | Context Prec. | Context Recall | Answer Corr. | Latency (ms) |
|---|---|---|---|---|---|---|
| **A — Basic** | **0.714** | **0.927** | 0.589 | **0.640** | **0.446** | **6 977** |
| **B — Advanced** | 0.661 | 0.764 | **0.777** | 0.460 | 0.436 | 17 892 |
| **C — Graph** | 0.698 | 0.690 | 0.685 | 0.420 | 0.414 | 17 751 |

**Конфигурация A — Basic:**  
`ENABLE_HYBRID=true`, `ENABLE_HYDE=false`, `ENABLE_RERANK=false`, `ENABLE_VERIFIER=false`, `ENABLE_GRAPH_EXPAND=false`

**Конфигурация B — Advanced:**  
`ENABLE_HYBRID=true`, `ENABLE_HYDE=true`, `ENABLE_RERANK=true`, `ENABLE_VERIFIER=true`, `ENABLE_GRAPH_EXPAND=false`

**Конфигурация C — Graph:**  
Все флаги Advanced + `ENABLE_GRAPH_EXPAND=true`

**Результат A/B:** гипотеза опровергнута по 4 из 5 метрик. Advanced проигрывает Basic по faithfulness (−7.4%), answer_relevancy (−17.5%), context_recall (−28.1%), answer_correctness (−2.2%) при +x2.6 latency. Единственный выигрыш — context_precision (+31.9%): Advanced более точно отбирает релевантные чанки, но теряет recall.

**Решение:** продакшн-конфигурация = Basic с verifier (`no_hyde_rerank`).

## 4. Ablation Study: 7 конфигураций

База сравнения: **Advanced (baseline faithfulness = 0.661)**

| Конфигурация | Отключено | Faithfulness | Δ | Вывод |
|---|---|---|---|---|
| `no_hyde_hybrid` | HyDE + hybrid | 0.559 | −0.102 | Критическая деградация: без semantic search + расширения запроса система слепа |
| `no_hybrid` | sparse BM25 | 0.583 | −0.078 | Hybrid критичен: юридические тексты требуют лексического матчинга (номера статей) |
| `no_verifier` | Self-RAG | 0.596 | −0.065 | Verifier полезен: без него LLM не проверяет grounding |
| `no_hyde` | HyDE expansion | 0.647 | −0.014 | HyDE слегка вредит на узких правовых вопросах |
| `no_rerank` | Cohere rerank | 0.657 | −0.004 | Rerank почти нейтрален на этом датасете |
| **baseline** | — | 0.661 | — | Advanced полная конфигурация |
| `no_rerank_verifier` | rerank + verifier | 0.680 | +0.019 | Rerank и verifier совместно добавляют шум |
| **`no_hyde_rerank` ★** | HyDE + rerank | **0.703** | **+0.042** | Оптимум: гипотетический документ вводит терминологический шум на специфичных правовых вопросах |

### Интерпретация результатов

**Почему `no_hyde_rerank` лучший?**

HyDE генерирует гипотетический ответ-документ для расширения запроса. На общих вопросах это помогает. Но на вопросах по НП ВС РК (специфичные правовые позиции Верховного Суда) гипотетический документ, сгенерированный LLM, вводит терминологические перефразировки, которые смещают векторный поиск от точных процессуальных формулировок.

Аналогично, Cohere rerank-v3.5 переупорядочивает результаты по cross-encoder score. На данном датасете это перемещает процессуально-правильные, но тематически смежные чанки выше конкретных цитат из НП ВС РК, снижая faithfulness.

**Отключение обоих вместе даёт синергию:** hybrid retrieval находит точные нормы лексически (BM25) и семантически (dense), verifier проверяет grounding, и без промежуточных трансформаций (HyDE, rerank) цепочка остаётся «чистой».

### Рекомендация для продакшна

```bash
ENABLE_HYBRID=true
ENABLE_HYDE=false
ENABLE_RERANK=false
ENABLE_VERIFIER=true
ENABLE_GRAPH_EXPAND=false
```

Ожидаемые метрики: faithfulness ~0.70+, latency ~7–9 сек.

## 5. Эксперимент с Graph Expansion

**Гипотеза:** кросс-документные рёбра (ТК РК ↔ Приказы Минтруда ↔ НП ВС РК) улучшат recall за счёт автоматического подтягивания связанных норм.

**Построение графа** (`scripts/build_cross_doc_edges.py`):
1. Двухшаговый LLM-матчинг (gpt-4.1-mini): `статья × документ → yes/no`
2. Детализация: `статья × параграфы → [список связанных пунктов]`
3. Рёбра сохранены в Qdrant payload как `linked_chunks`

**Результат:** Graph регрессирует относительно Basic по всем метрикам:

| Метрика | Basic | Graph | Δ |
|---|---|---|---|
| faithfulness | 0.714 | 0.698 | −0.016 |
| answer_relevancy | 0.927 | 0.690 | −0.237 |
| context_recall | 0.640 | 0.420 | −0.220 |

**Причина:** граф добавляет тематически связанные, но не более релевантные к конкретному вопросу чанки. На вопросах по НП ВС РК (процессуальные нормы) граф подтягивает материально-правовые нормы ТК РК — корректные в доменном контексте, но избыточные для конкретного вопроса. LLM «видит» больше источников и отклоняется от точного ответа, снижая faithfulness и answer_relevancy.

**Вывод:** graph expansion полезен для широких аналитических запросов («как связаны ст. 52 ТК и ст. 86 КоАП?»), но деградирует как глобально применяемое усиление к любому запросу.

## 6. Воспроизведение результатов

```bash
# Полный прогон всех 3 конфигураций
uv run python scripts/run_ragas_evals.py

# Только scoring из сохранённых входных данных (без re-retrieval)
uv run python scripts/run_ragas_evals.py --score-only

# Результаты
ls data/evals/ragas_final_*.json
ls data/evals/ragas_ablation_*.json
```

Для ablation — запустить с нужными feature flags через переменные окружения:
```bash
ENABLE_HYDE=false ENABLE_RERANK=false uv run python scripts/run_ragas_evals.py
```
